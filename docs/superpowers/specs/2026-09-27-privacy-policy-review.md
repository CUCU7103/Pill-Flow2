# 개인정보 처리방침 법적 검토 (2026-09-27)

> 대상: `artifacts/pillflow/public/privacy.html`
> 방식: 서브에이전트가 한국 개인정보 보호법(2026. 9. 11. 시행본)·시행령·개인정보보호위원회 「개인정보 처리방침 작성지침」(2025.4.)과 저장소 코드를 대조해 검토했다.
> **법률 자문이 아닌 참고 의견이다.** 게시 전에 개인정보 전문 변호사 또는 개인정보보호위원회 상담 창구에서 확인받는다. 조문은 law.go.kr 원문과 대조한다.

## 1. 요약

- **[높음] 민감정보 별도 동의가 없다.**
  - 복약 정보는 제23조의 "건강에 관한 정보"일 가능성이 높다. 그렇다면 계약 이행 목적이라도 별도 동의를 받아야 한다.
  - 앱에 동의 UI가 없다.
  - 처리방침 문구만으로는 해결되지 않고, 앱 기능을 추가해야 한다.
- **[높음] 국외 이전(제28조의8)과 처리위탁(제26조)을 고지하지 않았다.**
  - 누락된 업체: AWS 도쿄, Groq(미국), Vercel, Supabase(리전 확인 필요)
  - 현재 "제3자 제공" 항목에 수탁자와 Google을 섞어 적었다.
- **[높음] 사실과 다른 문장이 있다.**
  - "RLS로 본인 데이터만 접근"은 실제 구조와 다르다.
  - 실제로 없는 "앱 활동 수집"을 적었다.
  - 사진 분석 기능이 빠져 있다.
  - "즉시 파기"라고 적었지만 로그와 백업 보관 기간이 있다.
- **[중간] 제30조·시행령 제31조 필수 기재사항이 빠졌다.**
  - 파기 절차·방법, 위탁, 국외 이전
  - 개인정보 보호책임자(성명·연락처)
  - 자동 수집 장치(localStorage·세션 토큰)
  - 권익침해 구제 방법, 시행일·변경 이력
- **[중간] 연령 조항이 맞지 않는다.**
  - "만 18세 이상"만 적혀 있고 연령 확인 장치가 없다.
  - 법이 기준으로 삼는 선은 만 14세 미만의 법정대리인 동의(제22조의2)다.
- **[중간] 탈퇴 절차가 가입보다 어렵다.**
  - 탈퇴는 이메일로만 받는다.
  - 제38조(요구 절차가 수집 절차보다 어렵지 않아야 함)와 Google Play 계정 삭제 요건에 맞지 않는다.

## 2. 코드로 확인한 사실관계

| 항목 | 확인 결과 |
|---|---|
| 사진 원본 저장 | 저장하지 않는다. 앱 메모리의 data URL로만 다루고, Edge Function이 Groq로 보낸 뒤 `{name, summary}`만 돌려준다. |
| 사진 관련 로그 | 이미지는 로그에 남지 않는다. Groq 오류 본문과 파싱에 실패한 모델 응답(`rawContent`)은 Edge Function 로그에 남을 수 있다. |
| Groq 보관 | 공개 문서 기준으로 기본 보관하지 않고 학습에도 쓰지 않는다. 오류·남용 조사 시 최대 30일까지 남길 수 있다. Zero Data Retention(ZDR) 설정 여부는 확인이 필요하다. |
| CloudWatch | `/pillflow/api` 로그 그룹, 14일 보관, 도쿄 리전. Caddy 접근 로그(IP)는 기본으로 남기지 않는다. |
| 탈퇴 시 삭제 | `auth.users` 기준 `ON DELETE CASCADE`라서 계정을 지우면 복약 데이터도 함께 삭제된다. |
| 분석 SDK | 없음 |
| 동의 UI | 없음 |
| Supabase·Vercel 리전과 로그 보관 | 확인 필요 |

## 3. 수정 방향 (조항별)

1. **처리 목적·항목:** 표로 정리한다.
   - 가입·로그인 / 복약 관리(민감정보) / 사진 분석(선택) / 자동 생성되는 오류 기록
   - 각 행에 처리 근거를 함께 적는다(계약 이행 또는 별도 동의).
2. **민감정보 조항:** 별도 동의로 처리한다는 점, 공개 기능이 없다는 점, 동의를 철회하는 방법을 적는다.
3. **보유 기간:** 항목별로 적는다.
   - 계정·복약 정보: 탈퇴 시까지
   - 사진: 저장하지 않음(Groq는 최대 30일 보관 가능)
   - 오류 로그: 14일
   - 백업: 기간 확인 필요
4. **파기 절차·방법:** 앱의 "복약 데이터 초기화"와 탈퇴 시 삭제되는 범위를 적는다.
5. **제3자 제공:** "제공하지 않음"으로 둔다. 수탁자는 여기서 뺀다.
6. **위탁·국외 이전:** 표로 적는다.
   - 칸: 이전받는 자·연락처 / 국가 / 항목 / 목적 / 시기·방법 / 기간
   - 대상: AWS(일본), Supabase(리전 확인), Groq(미국), Vercel(확인)
   - 근거: 제28조의8 제1항 제3호 가목(처리방침 공개)
   - 거부 방법과 그 효과도 적는다. 사진 분석을 쓰지 않으면 Groq로 이전되지 않는다.
   - Google은 로그인 수단이므로 따로 설명한다.
7. **정보주체 권리:** 열람·정정·삭제·처리정지·동의 철회를 적는다. 앱 안의 삭제 경로, 탈퇴 요청 절차·기한·본인 확인 방법, 대리인 행사 방법도 함께 적는다.
8. **아동:** 만 14세 미만은 가입할 수 없다고 적는다(동의 화면에 확인 체크 추가 권장). 수집 사실을 알게 되면 지체 없이 파기한다는 문장도 넣는다.
9. **안전성 확보 조치:** 다음을 적는다.
   - HTTPS
   - 서버가 JWT를 검증하고 본인 데이터만 처리하도록 제한, DB RLS 병행
   - DB 계정 최소 권한, 비밀값은 SSM으로 관리
   - SSH 포트 미개방
   - 저장 데이터 암호화 여부(확인 후 기재)
10. **자동 수집 장치:** localStorage(다크 모드·알림 설정·인증 토큰), 기기 로컬 알림, 거부하는 방법을 적는다.
11. **개인정보 보호책임자:** 성명(또는 직책)과 연락처를 적는다.
12. **권익침해 구제 방법:** 개인정보분쟁조정위원회(1833-6972), 개인정보침해신고센터(118), 대검찰청(1301), 경찰청(182)을 적는다. 게시 전에 번호를 재확인한다.
13. **변경 고지:** 시행일, 변경 이력, 사전 고지 기간을 적는다.

privacy.html에 바로 넣을 수 있는 HTML 초안은 검토 원문에 있다. 필요하면 다시 생성을 요청한다.

## 4. 운영자가 결정·확인할 사항

1. Supabase 프로젝트 리전과 Edge Function 실행 위치(대시보드 Settings → General)
2. **민감정보 별도 동의 UI(1순위):** 동의 시점, 동의 기록 저장, 기존 계정 3개의 재동의 방법
3. 연령 기준: 만 14세 미만 가입 불가로 바꿀지, 18세 기준을 유지할지
4. 보호책임자를 실명으로 공개할지, 전화번호를 적을지
5. 보유 기간: 탈퇴 처리 기한, Supabase 백업·Edge Function 로그·Vercel 접속 로그 보관 기간
6. Groq ZDR을 켤지
7. 위탁 문서(각 업체 DPA·약관으로 갈음 가능한지)와 각 업체의 개인정보 문의 연락처
8. 앱 내 탈퇴 기능 구현 일정(Google Play 요건 포함)
9. 기존 이용자에게 AWS 도입(2026-09-27)을 알릴 방법. 제28조의8 제3항이 적용되는지 확인 필요
10. 저장 데이터 암호화 적용 여부
11. Edge Function의 `console.error(rawContent)` 로그를 유지할지

## 5. Google Play 데이터 보안 섹션 참고

- 수집 항목:
  - 개인 정보: 이름, 이메일, 사용자 ID
  - 건강 정보: 복약
  - 사진: 일시적으로 처리하고 저장하지 않음
- 앱 활동과 기기 ID는 수집하지 않는다. 현재 처리방침의 "앱 활동 수집" 문구와 충돌한다.
- 전송 중 암호화: 예
- 계정 삭제: 앱 안과 웹 양쪽에 경로가 필요하다.
